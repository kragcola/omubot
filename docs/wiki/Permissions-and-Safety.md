# 权限与安全边界

权限、证据和数据一致性是原生业务合同，不作为可关闭插件，也不因情感或体验目标放宽。

## 一次动作需明确什么

可信主体、动作种类、目标、会话范围、用途和期限。模型上传、QQ 发送、mention、网络读取/写入及记忆消费可能需要不同许可，不能用一个功能开关代替全部授权。

群与私聊默认隔离。关系好、重复教学、角色故事或工具建议都不改变权限。管理操作继续使用原认证入口，不从聊天内容信任管理员身份。

## 撤权与轮次失效

运行中的动作在所属边界核对当前权限、来源期限和轮次版本。撤权或来源失效传播到未提交任务；重新授权不让旧贡献或过期候选复活。

已保存配置不改变正在使用的快照。业务状态、意图、成本和审计按同一事务合同提交，不在数据库事务里等待外部网络。

## 失败状态

| 状态 | 意义 | 后续 |
| --- | --- | --- |
| denied | 权限或业务门未允许 | 记录原因，不绕过 |
| failed | 有明确失败结论 | 保留原尝试，按任务范围处置 |
| cancelled_before_dispatch | 外部发送前取消 | 不宣称已发送，也不自动补发 |
| unknown | 已可能执行，但缺确定结果 | 保留原动作、成本与审计；QQ 投递由 QQ owner 停发并人工核验，其他外部结果按所属 owner 处置，不自动重放 |
| succeeded | 动作取得成功结果 | 仍需业务提交或实际接收证据，才能认定该用例通过 |

QQ held 是持久停发保护。不能清计数、核销 unknown、换账号、降限频或自动重放来制造成功；受控测试同样遵守。

## 隐私与运行数据

只在获准用途和期限内读取正文，测试记录优先保留 ID、摘要与安全结果码，不将私密原文、密钥、凭据、真实账号或实例数据库上传公开仓库。

运行 SQLite 用 `mode=ro` 阅读并考虑 WAL，不使用 immutable 伪造静态快照，也不直接写运行库。备份和恢复见 [Deployment](Deployment.md)。

上述边界不是对第三方协议、模型或任意插件的安全沙箱保证；外部账号风险与平台限制仍需实际核验。
