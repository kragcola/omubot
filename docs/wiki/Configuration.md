# 配置

配置保存、运行配置和业务权限是三个不同状态。

## 两种配置职责

| 类型 | 内容 | 归属 |
| --- | --- | --- |
| 启动身份 | 实例、Bot 身份、端口、数据目录等 | 实例初始化与启动配置 |
| 日常配置 | 命名模型、任务绑定、人格和能力设置等 | 首次导入后由 Web / SQLite 配置版本服务管理 |

日常配置首次导入后，不靠再次修改 TOML 覆盖数据库中的已保存版本。Web 也不能通过日常配置改实例身份、数据库路径或运行模式。

## 保存与应用

1. 编辑草稿时绑定原始 revision。
2. 保存统一校验并生成新 revision；冲突明确拒绝覆盖。
3. 核对已保存版本和当前运行版本。
4. 在受管运行入口应用已保存配置；有活动任务时拒绝。
5. 核验新核心实际版本、依赖与连接，而不是只看保存成功。

当前采用核心重建后生效。重建会更换管理会话并清空短期内存历史，需要重新登录；独立 NapCat 的登录态不应因此中断。回滚配置同样生成版本，不直接覆盖运行中的请求。

## 模型

支持多个命名配置，可给回复、Thinker、视觉等任务绑定模型；未绑定任务按既定默认配置处理。已实现 OpenAI Chat Completions / Responses、Anthropic Messages、DeepSeek Chat 的必要协议子集，不承诺供应商所有扩展均兼容。

完整请求端点与模型名必须明确。密钥可以通过配置的环境变量或 Web 模型设置提供；Web 保存的值留在该实例私有 `model-secrets.json`，环境变量优先。密钥不写入日常配置库，也不进入公开源码。保存新端点不为其自动授权，任务实际使用的目的地也要核验。

## 能力开关不是授权

功能已开启仍可能因缺依赖、缺来源、账号 held、目标未授权或限频而不能执行。群与私聊默认隔离，跨域共享必须明确；主动联系另需用户与群双授权。

第三阶段固定长窗内禁止随意换模型、人格、配置或候选，避免把不同版本拼成一个稳定结果。当前能力状态见 [Status](Status.md)。
