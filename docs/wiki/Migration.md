# 新旧迁移

新项目是独立重构，旧项目是行为、数据含义、体验基准与历史证据来源。不是更换目录名称，也不是保留旧平台后继续堆兼容分支。

## 为什么创建

旧版功能积累快，但后续代码、配置和运行状态的归属更难理解，门禁与外部副作用的生命周期需要重新建立一致性。重构目标是让自然聊天与可维护、可核验的运行链同时成立。

旧版使用体验是新版的重要基准。结构更简洁或测试更多不能抵消聊天质量退步；新版仍需读实际回复、比较流程与效果，再逐步发布。

## 继承与重新实现

| 继承 | 不自动继承 |
| --- | --- |
| 已确认功能目标、行为约定、问题经验 | 旧实现已完成的声明 |
| 有效的立项、后续修订、验收记录 | 历史 ACTIVE、暂停任务或旧执行权限 |
| 数据含义与迁移映射 | 旧数据库、密钥、登录态与部署身份 |
| 有来源和验证收益的必要复用 | 整目录旧业务、NoneBot2 / PluginBus 骨架 |
| 旧版实际体验基准 | 旧版本号、包数、Docker 默认拓扑与运行命令 |

79 项功能映射用于防遗漏，不代表 79 个模块、全部批准或全部实现。延期、替代、排除与未验条目继续保留；新版不恢复任意动态插件安装、旧控制平面或未获准暗态能力。

## 本次 GitHub 更新范围

此前先发布 README 与新版 Wiki；随后按用户要求，将 `main` 的活动文件整体替换为当前运行候选对应的白名单源码。包括 Python 核心、前端源码与预构建静态资源、依赖锁、通用配置、必要构建检查、README 与 `docs/wiki/`。沿用原 MIT LICENSE，旧实现和旧文档仍可从 Git 历史回看。

不上传个人实例、密钥、数据库、QQ 登录态、人格资产、缓存、完整开发测试与内部审计记录。旧 NoneBot2 / PluginBus 目录、Compose 拓扑和依赖旧测试的 CI 不再留在新版活动树；本次不另造未验证 CI。

旧代码及 README 保留在主仓库提交历史；新版源码替换前的主分支提交为 `e55ba8229d1844caebe401435022665e6a24b516`。最初旧 Wiki 提交为 `e62af5aa2299f22e8211df5aa1e56fb347e74296`，各轮文档历史保留。旧内容不作为当前部署指南。发布核对源码与运行候选身份、导出白名单、原许可证、依赖与默认配置；平台和真实业务验收仍未齐。

## 迁移前必须保留

当前来源与 revision、WIP、真实外部动作、撤权、成本、unknown 和审计。未迁移旧生产数据不代表可以删掉；新状态也不能为了回滚被旧快照覆盖。
