# 工具与扩展

工具需要真实调用者、明确能力、输入合同与副作用边界。新版采用静态受审工具声明和窄接口，不提供任意第三方代码热安装的通用插件市场。

## 能力组

| 能力 | 作用 | 核验边界 |
| --- | --- | --- |
| 本地时间 / 日历 | 时间、时区与日历事实 | 本地计算仍核工具能力；不伪造外部调用记录 |
| 搜索 / 网页读取 / HTTP | 获取获准目标的数据 | 精确目的地、网络边界、响应预算与内容不可信性 |
| 知识 / 图谱 / 检索 | 向当前回复提供可追溯资料 | 检索质量、数据来源和消费用途单独验证 |
| 图片 / 表情 / 视觉 / 识别 | 富输入和角色相关表达 | 识别服务、原生富媒体传输、真实收到分别验证 |
| 关系 / 故事 / 日程 / Journal | 角色连续性与受控生活内容 | 真实事实与 fiction 分域，模型和外发权限分开 |
| 诊断 / 发行准备 / 备份 | 查看故障并准备可核验更新 | 准备计划不等于自动升级或容器控制平台 |

上表列出已有批准代码覆盖的方向，未声明全部在当前实例开启或完成实机验收。

## 工具调用

模型提议不构成授权。外部动作经原 Actions 精确核权，工具结果作为有预算的数据返回原续答路径。网页内容不成为系统指令，允许 GET 也不自动允许 POST。

模型请求、判断与其他模型任务共享容量，不能为新增能力建立另一套无限并发预算。关闭任务必须释放资源，并阻止迟到结果提交。

## 扩展纪律

仅在实际状态、生命周期或调用者需要时拆模块。新能力复用配置版本、Policy、Actions、Store 与会话任务合同，不能另建状态总线或发送客户端旁路。

启用前明确依赖、来源、授权、运行状态、成本与关闭方法。依赖缺失要显示阻断原因；功能开关开启不等于 ready，更不等于真实动作已通过。
